# OWASP Top 10 Mapping

How SecureNotes handles each risk in the [OWASP Top 10 (2025)](https://owasp.org/Top10/2025/), the most widely used list of critical web application security risks.

Each row links the risk to the threats in the [threat model](threat-model.md) (e.g. **I1**), the defences in the code, and the evidence that they work: automated tests, CI, and the [self-pentest](pentest-report.md) (e.g. **P1**).

| # | Risk | How it could hit SecureNotes | Defences | Evidence |
|---|---|---|---|---|
| **A01** | **Broken Access Control** | Bob reads, edits or deletes Alice's note by changing the ID in the URL (IDOR); a reader edits a note shared with him | Every note lookup checks ownership in the SQL query itself: `get_owned_note()` for edit, delete, share and revoke, and `get_readable_note()` (owner or shared) for viewing only. Unknown and forbidden notes both return the same 404. `login_required` on every private page. *Threats I1, I2, T1, E1, E2* | `tests/test_notes.py`, `tests/test_sharing.py`; pentest P1–P3 |
| **A02** | **Security Misconfiguration** | Debug mode on in production; missing security headers; secrets in the repo | Debug off outside local development; strict Content-Security-Policy, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`, `Cache-Control: no-store`; the app refuses to start without a `SECRET_KEY`; `.env` excluded from Git and from the Docker image; the container runs as a non-root user. *Threats I5–I8, S3* | `tests/test_headers.py`, `tests/test_factory.py`; pentest P8–P9, F3 |
| **A03** | **Software Supply Chain Failures** | A vulnerable or compromised package or GitHub Action | All package versions pinned; **pip-audit** checks them for known vulnerabilities on every push; GitHub Actions pinned to commit hashes, with read-only permissions. *Threat T4* | CI security job (`.github/workflows/ci.yml`) |
| **A04** | **Cryptographic Failures** | Passwords readable if the database is stolen; session cookies forged or sent over plain HTTP | Passwords stored only as **argon2id** hashes (RFC 9106 settings, random salt); cookies signed with a random secret key; `Secure` cookie flag on by default (HTTPS only). *Threats I4, S2, S3* | `tests/test_auth.py` (hash format, cookie flags) |
| **A05** | **Injection** | SQL injection through a form field; a script hidden in a shared note (XSS) | **Parameterised SQL** everywhere (no string building); Jinja2 **auto-escaping**, with the CSP as a second layer that blocks all scripts. *Threats T3, I3* | Bandit in CI; pentest P5 |
| **A06** | **Insecure Design** | Security added as an afterthought, missing whole classes of attack | STRIDE **threat model written before the feature code**; secure design choices such as read-only sharing, no password reset by email, no admin role, and usernames instead of emails (less personal data). See the 50 design decisions in the [README](../README.md#design-decisions) | `docs/threat-model.md` |
| **A07** | **Authentication Failures** | Password guessing and credential stuffing; session fixation; a stolen cookie that keeps working after logout | Minimum password length 12; login rate limited **per IP and per username** (cooldown, not lockout); one generic login error plus equal timing for unknown usernames; session cleared at login; **logout invalidates every cookie for that user** (`session_version`, added after pentest finding F1). *Threats S1, S4, S5, S6, D1* | `tests/test_rate_limits.py`, `tests/test_auth.py`; pentest P6–P7 |
| **A08** | **Software or Data Integrity Failures** | Cross-site request forgery makes the user's browser change their data; a tampered session cookie | **CSRF tokens** on every form (Flask-WTF, app-wide); `SameSite=Lax` cookies; logout is POST-only; signed session cookies reject any change; the owner always comes from the session, never from the form. *Threats T2, S3* | `tests/test_auth.py`, `tests/test_notes.py`; pentest P4 |
| **A09** | **Security Logging and Alerting Failures** | Attacks happen and nobody can tell afterwards | **Security event log** (JSON lines) of logins, failed logins, logouts, shares, revokes, deletions, denied note access, rate-limit hits and rejected CSRF tokens; no passwords or note contents logged; protected against log injection. *Threat R1* | `tests/test_audit.py`; pentest P1, F2. **Gap:** events are logged but nobody is alerted; a real deployment would send them to a monitoring system |
| **A10** | **Mishandling of Exceptional Conditions** | Errors that leak internal details, or a crash caused by huge or unexpected input | Debug pages off; generic 404, 413 and 429 responses; size limits on usernames, passwords, notes (10,000 characters) and whole requests (256 KB); database errors such as a duplicate username are caught and shown as a friendly message. *Threats D2, I5* | `tests/test_notes.py` (size limits), `tests/test_auth.py` |

## Not applicable

- **Server-side request forgery** (part of A01 in 2025): the app never fetches URLs supplied by users.
- **Insecure deserialisation** (part of A08): the app never deserialises untrusted data. Session cookies are signed JSON, not pickled Python objects.
